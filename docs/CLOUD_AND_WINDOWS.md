# RPG: Windows ↔ GitHub ↔ Codex Cloud

Единственный опубликованный источник прогресса — приватный `Yerrinend/Hogwarts-RPG`, ветка `main`. Репозиторий не делает личную переписку доступной публично. Запрещены force push, автоматическое стирание файлов и одновременная игра на двух устройствах.

## Подготовка Codex Cloud

В веб-версии/desktop: Work in → Cloud → Select environment → Create environment (или Settings → Codex Cloud → Environments). Выберите **только Hogwarts-RPG**, подключите GitHub, если нужно. Get started → проверьте setup → Publish → дождитесь Environment published. Доступ окружения оставить Only me.

Текст для setup:

> Это приватная текстовая RPG, без приложения и сервера. Нужны Python 3.12+ и Git, UTF-8. Не продолжай сюжет. Не запускай архивные скрипты восстановления. Выполни python scripts/rpg_sync.py validate. Проверь fetch origin main и доступный механизм Commit/Create PR. Не добавляй токены в репозиторий и не выдавай широкие права. Публикуй окружение только после проверки. Основные файлы rpg/state.json и rpg/quick_save.md.

Доступ к GitHub для синхронизации необходим; разрешение сетевого домена само по себе не даёт прав записи. Существующий вход Windows не переносится в Cloud. Если среда позволяет push, `save` делает его и проверяет SHA. Если не позволяет — штатные Commit/Create PR и ручное Merge после успешной проверки. Не вставлять токен в чат, файлы или командную строку URL.

Официальные инструкции: https://learn.chatgpt.com/docs/environments/cloud-environments . Каждая новая задача имеет отдельные файлы; существующая задача может хранить старое состояние. Перед каждым новым ходом обязательна проверка актуального main, а не надежда на автоматическое обновление среды.

## С телефона

1. Откройте Codex в том же ChatGPT-аккаунте, выберите опубликованное окружение Hogwarts-RPG.
2. Запрос: «Прочитай AGENTS.md. Выполни scripts/rpg_sync.py start, затем продолжи RPG с актуального quick_save.md. Мой выбор: …». До успешной проверки основы сюжет не продолжать.
3. После главы агент сохраняет память, делает коммит с номером и пытается отправить его. Если виден `PUSH_VERIFIED`, проверка main пройдена.
4. Если вместо push доступен PR, нажмите **Create PR**, откройте его в GitHub, дождитесь зелёной **RPG save integrity**, проверьте изменения и нажмите **Merge pull request**. Только теперь переходите на ПК. Ссылка на PR — промежуточный результат, не завершённая синхронизация.
5. Старый облачный чат после локального хода не продолжать без обновления основы. Надёжнее начать задачу от актуального main; сама история хранится в файлах.

## На Windows

- При входе в Windows задача `HogwartsRPG-Sync-Logon` (если зарегистрирована) выполняет только безопасный pull. Журнал результата — локальный `.local/startup-sync-status.txt`. При сетевой ошибке обновления нет.
- Перед открытием проекта можно запустить **Start-RPG.cmd**. При ошибке он останавливается; при успехе открыть рабочую папку в Codex.
- Перед игровым ходом агент выполняет `start`, после — `save --chapter N`. В Windows используйте настроенный Python и `scripts/windows_entry.py start` / `save --chapter N`; `Start-RPG.cmd` сам находит Python через локальный JSON. Политика этой машины запрещает `.ps1`, поэтому задача входа вызывает `pythonw.exe` напрямую, без изменения политики. `.local/runtime.json` с путями только локальный, не публикуется.
- Если ответ сообщает об ошибке прав песочницы, повторить именно Git-операцию с разрешением среды, а не обходить защиту или удалять незавершённый ход.
- С ПК на телефон: после главы нужен подтверждённый push main. Затем в Cloud обновить/начать задачу от main и выполнить start. Одного сохранения файлов на диске недостаточно.

## Конфликты и восстановление

- Dirty working tree: pull отказывается менять файлы. Сначала сохранить изменения и поручить агенту разобраться, законченный ли это ход или технические правки.
- Незавершённый ход: `.local/active-turn.json` не позволяет начать ещё один. Если коммит уже создан, `publish` повторяет отправку без нового коммита/главы. После PR/ручной отправки повторить publish для проверки, когда это возможно.
- Remote advanced: не force push и не автоматическая склейка двух версий одной главы. Сохранить локальный коммит/ветку, выяснить, какую ветку истории выбирает игрок, и только затем согласовать сохранения.
- Перед fast-forward создаётся локальная ветка `backup/before-pull-*`; первоначальный ZIP находится локально в `backups/`. Они не отправляются на GitHub. Перед ручным восстановлением сделать новую копию; не выполнять reset --hard без отдельного решения.
- Проверка PR сравнивает квитанцию хода с актуальным main. Если другая глава уже опубликована, старый PR должен остановиться. Обязательность зелёной проверки на стороне GitHub зависит от настройки защиты ветки; без неё нельзя считать серверную блокировку гарантированной.
- Текстовый Git-конфликт нельзя разрешать только выбором более поздней даты: сверять согласованность state, quick_save, current_save, таблиц и журнала.

## Границы публикации

Публикуются правила, канон, обзоры этапов, хронология, характеристики, сохранения и код синхронизации. HTML, полная выгрузка переписки, исходные текстовые свидетельства, восстановительные скрипты, локальные пути, токены, логи и ZIP не публикуются. В Cloud ссылкам на локальные исходники может не соответствовать файл; при неразрешимом вопросе обращаться к локальному источнику, не выдумывать ответ.

Правила AGENTS.md — инструкции агенту, не постоянно работающая служба. Они действуют при выполнении игрового хода агентом; сами по себе не запускают push в закрытом приложении.
