# Передача отдельных взрослых сцен: ChatGPT ↔ внешняя модель (Grok) ↔ ChatGPT

## Назначение
Это **система сохранения непрерывности RPG**, а не приглашение переписывать канон или готовая уже сыгранная интимная сцена. Её можно использовать, когда игрок **самостоятельно** решит продолжить отдельную сцену во внешней модели. Графические описания не обязательны и не хранятся здесь по умолчанию.

**Текущая точка:** глава 460, четверг **19.12.1991 ~20:56**, галерея возле библиотеки. Драка ждёт ответа Стаса, будут ли они готовить праздник 20.12 до 17:00 отдельно или частично вместе. **Никакая передача ещё не активирована.** Последний полный репозиторный сейв — глава **454**; очередной полный сейв — после **464**. `rpg/state.json` намеренно старше чата. Прежде чем продолжать после 460, использовать **CURRENT_CONTEXT_460.md**.

## Процедура
1. **Обычная RPG здесь продолжается.** При появлении подходящего эпизода ассистент может обозначить возможную точку передачи, но **не передаёт автоматически** и не решает за Стаса.
2. По выбору игрока делается **точный снимок сцены**: файл `HANDOFF_STATE.md` с датой, минутой, местом, всеми свидетелями, точными словами последних реплик, незавершёнными решениями, актуальными отношениями, запретами на знание и соседними сюжетными арками. Снимок создаётся **до внешней сцены** и не подменяет полный сейв.
3. Игрок отправляет внешней модели **ссылки или содержимое** пакета и, при необходимости, полных канонических файлов. Важно: **ссылка сама по себе не гарантирует, что внешняя модель прочитала содержимое**; если доступа к GitHub нет, копировать содержимое текста. Запросить у внешней модели подтверждение ключевых фактов перед началом.
4. Игрок самостоятельно принимает решения за Стаса во внешнем эпизоде.
5. При возврате игрок присылает текст и/или **сюжетное резюме без графических подробностей** по шаблону; ассистент сверяет хронологию и согласие, отделяет факты от предложений, записывает согласованный **неграфический** канонический итог.
6. Продолжение с точного времени финала внешней сцены. Не переписывать реплики и решения; при противоречии с каноном сначала отметить конфликт и согласовать канонический статус.

## Защита от потери контекста
- Не полагаться на память модели: хранить **актуальный CURRENT_CONTEXT_NNN.md + отдельный HANDOFF_STATE.md + журнал завершённых событий**.
- Перед началом внешняя модель должна назвать **последнюю сыгранную главу, дату, место, факты о Драке/Элли, подарках, 23.12, Хогсмиде и числах**, чтобы пользователь увидел пропуски.
- Различать **CONFIRMED / OPEN / PLANNED / PRIVATE / PROPOSED**. Слова «может» или «планируется» не значат «произошло».
- Большие файлы могут не открыться целиком. Пакет содержит краткую проверяемую сводку, но если появляется конфликт, основная история имеет приоритет.
- Не записывать подробный эротический текст в публичный GitHub по умолчанию: репозиторий может быть доступен посторонним. Сохранение подробной копии только по отдельному решению пользователя и правилам платформы.
